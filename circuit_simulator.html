Circuit Simulation Software

C++ circuit simulator using Modified Nodal Analysis and numerical simulation

Overview

I developed a circuit simulation program in C++ designed to simulate electrical circuits without relying on an existing circuit simulation engine. The simulator uses Modified Nodal Analysis to mathematically solve the circuit and numerical methods to simulate and record its behavior and values.

The project began as an attempt to better understand how circuit simulation software works internally. Rather than treating a simulator as a black box, I wanted to replicate the math and understand it on a deeper level.

Design Goals

  • Simulate electrical circuits using C++
  • Find a method to represent circuit components mathematically
  • Support multiple electrical component types
  • Simulate second order circuits
  • Provide a graphical representation of circuits
  • Display simulation results graphically
  • Build the simulation engine without relying on an existing SPICE engine

How the Simulator Works

The simulator represents an electrical circuit as a mathematical system of equations. The circuit is analyzed using Modified Nodal Analysis, which allows the voltages and currents within the circuit to be solved using a matrix-based system. Once the currents and voltages are solved for a given time step, the results are then funneled back into the solver to update components that depend on changes in voltage or current for the next time step.

Modified Nodal Analysis

Modified Nodal Analysis (MNA) is used to convert the electrical circuit into a system of equations that can be solved computationally.

Each component contributes (stamps) values to the system of equations based on its electrical characteristics and the nodes to which it is connected. In my simulator the system of equations represented by a matrix where rows and columns correspond to component currents or node voltages in the circuit.

For example, a resistor contributes a conductance to the matrix based on the formula:

G = 1 / R

The resistor stamp is implemented like this, where node i and j correspond to a row/column in the matrix. The matrix is updated to add or subtract G according to this chart's columns. The simulator uses these relationships to construct the MNA matrix by stamping each component's values into it, which is then solved to determine the unknown circuit voltages and currents. Each component has its own stamp, however, this is the general idea behind stamping.

Transient Simulation

DC analysis alone is not enough for circuits containing components whose behavior changes over time. The simulator has the ability to perform transient analysis by repeatedly solving the circuit at discrete time intervals.

Each simulation step uses the previous state of the circuit to determine the values for the next time step. I used Backward Euler as the numerical integration method for approximating the behavior of dynamic components like capacitors and inductors.

Software Architecture

The simulator is divided into three main sections: the UI, controller, and solver. Each section has a specific responsibility, allowing the user interface, application logic, and circuit simulation to remain separated from one another.

  • UI - Handles user interaction and visual circuit representation
  • Controller - Manages application logic and directs user requests
  • Solver - Builds and solves the mathematical representation of the circuit

User Interface

The UI is responsible for interacting with the user and displaying the current state of the circuit. User actions, such as placing a component, moving a component, or starting a simulation, are converted into requests for the controller to process.

Controller

The controller acts as the central point between the UI and the rest of the simulator. Instead of allowing the UI to directly modify the circuit or communicate with the solver, user actions are represented as commands that are passed to the controller.

The controller then determines what needs to be done and passes the request to the appropriate handler. For example, when the user chooses to place a new component, the UI generates a request indicating that a new component needs to be placed. The controller receives this request and passes it to the component placement handler, which is responsible for carrying out the operation.

This separation prevents the UI from directly communicating with the solver and keeps individual operations isolated from one another.

Solver

The solver is responsible for the electrical simulation itself. It takes the circuit represented by the application and converts it into the mathematical system used for simulation. This includes constructing the Modified Nodal Analysis matrix and solving for the circuit variables.

Request Flow

A user action follows this general path:

User → UI → Controller → Handler → Circuit

For example, placing a new component begins with the user selecting the component through the UI. The UI creates a request for a new component, which is received by the controller. The controller then passes the request to the component placement handler, which performs the necessary operations to add the component to the circuit.

This architecture keeps the different parts of the simulator independent and makes it easier to modify or add functionality without requiring the UI and solver to directly depend on one another.

Visualization

The simulator includes a graphical interface that allows circuit behaviors to be represented visually as well as analyzed with a oscilloscope style cursors

Testing and Debugging

The simulator was tested using simple circuits whose behavior could be calculated independently. This allowed the simulation results to be compared against theoretical values.

Example test circuits include:

  • Resistive voltage divider
  • RC charging circuit
  • RL circuit
  • RLC circuit
  • DC voltage source circuits
  • Time-varying source circuits

Testing individual circuits also helped identify problems in the matrix construction, numerical solver, component models, and simulation timestep.

Results

The completed simulator is capable of constructing and solving electrical circuits using the implemented numerical methods.

Problems and Improvements

This version of the circuit simulator is actually a rewrite of the original. My first attempt at the simulator was a success in a way, but its architecture made it increasingly difficult to add new features and component types. I rewrote the whole simulator to improve its structure, maintainability, and ability to support additional simulation features.

One specific problem with the first version was that the simulation was tied directly to real-world time. Because the simulation progressed as the program was running, it was difficult to save simulation data or reproduce an identical simulation later which made debugging and verification of functionality a difficult task. Small differences in timing could also affect the resulting data.

In the rewritten version, the simulation is separated from the user interface and controlled using defined simulation time steps. This makes the simulation more deterministic and allows simulation data to be recorded, analyzed, and reproduced more reliably.

What I Learned

This project gave me practical experience with numerical methods, circuit analysis, software architecture, and C++ programming.

The project showed me the importance of software architecture. Separating the UI, controller, handlers, and solver made the simulator significantly easier to modify and allowed new functionality to be added without tightly coupling unrelated parts of the program.

Another major part of the project was debugging. Many problems could not be solved simply by looking for a syntax error; I often had to determine whether the problem came from the circuit equations, matrix construction, node connection lists, solving methods, or the program itself. Comparing the simulator's results against circuits with known solutions became an important part of testing and debugging the program.

Overall, this project helped me develop a stronger understanding of the relationship between electrical engineering and software development. Building the simulator from the ground up allowed me to see how circuit theory, linear algebra, and numerical analysis can be combined to create a practical engineering tool.
